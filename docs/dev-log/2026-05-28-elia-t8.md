## What changed

### 1. New `apps/lumen/internal/metrics` package (~280 lines + tests)
- `Histogram` — fixed-capacity reservoir-sampled latency distribution (Vitter R). cap=4096 keeps memory bounded at ~16 KiB per histogram while statistical error on p99 stays under ~1 percentile point at T8 sample volumes (60s × ~100 bids/s ≈ 6k samples).
- `Counter` (`atomic.Int64`) and `Registry.StreamLenMax` (CAS-bounded monotonic gauge).
- `Snapshot` — JSON shape consumed by `/metrics` and by the load harness. Field names are the source of truth for any scraper.
- Tests: percentile-exactness-at-cap (anchors the nearest-rank math), reservoir-bounded-memory (regression net for the OOM-under-sustained-load case), statistical accuracy at N=60k cap=4096, negative-clamp behaviour (documented at the call site for clock skew), concurrent-Observe (race detector picks up an unprotected `samples` slice), shape pinning (rename = compile-time miss but JSON-shape break).

### 2. Hot-path instrumentation (V9 §4.2 SLO instruments)
| Metric | Site | What it measures |
|---|---|---|
| `ackLatencyMs` p95 < **80 ms** | `dispatchWS` BID_PLACE | server-side processing: envelope decode + Lua dispatch + ack push |
| `broadcastLatencyMs` p95 < **150 ms** | `Hub.subscribe` fanout | `now - payload.serverTimeMs` (Lua-authoritative Redis TIME). Records once per fanned-out event. |
| `hammerLatencyMs` p95 < **500 ms** | `closeDue` on OK_SOLD/OK_NO_BID | `now - endAtMs` at close commit — detection lag + Lua exec (fanout adds the broadcast component) |
| `catchupLatencyMs` p95 < **1 s** | ROOM_JOIN catchup branch | snapshot read + Stream replay + push, only when `lastSeq > 0` and ≥1 event actually replayed |
| `placeBidScriptTimeMs` p99 < **5 ms** | `Store.PlaceBid` via WS | Go-side EVALSHA round-trip — V9 §4.2 footnote pre-gate for ack p95<80 |
| `seqGapCount` = **0** | Hub.subscribe fanout | Increments by (gap-1) when a fanned-out seq jumps from lastSeq by more than 1. §4.1 0-tolerance. |
| `bidsAccepted` / `bidsRejected` | dispatchWS | DUPLICATE does NOT bump `bidsAccepted` (it's a replay, not a fresh accept). |
| `backpressureForceClose` | `Conn.trySend` overflow | T5 force-close counter, tied here so the load report can correlate slow-client trims with ack-p95 spikes. |
| `streamLenMax` | Hub.subscribe sweep | Peak XLEN observed; AOF/Persistence-lag proxy. |
| `activeConns` | WS upgrade/defer | Current connection gauge. |

All Observe / Inc sites are `if m != nil` so unit tests can wire `Hub`/`Conn`/`runTimerWorker` without a registry. Test asserts the nil-safety so a future refactor that accidentally removes the guard fails.

## Review pass (docs/review.md)

- **Contract drift** — none. Lua scripts untouched; envelope shape unchanged; state-machine unchanged; `proto/error-codes.md` untouched. Metrics is internal observability surface (V9 §4.3 says it must exist; doesn't specify shape).
- **Correctness** — Histogram is reservoir-sampled with the textbook Vitter R algorithm; the unit tests cover the boundary (`n < cap` exact, `n >> cap` bounded, statistical accuracy at the documented cap). seqGap delta math is asymmetric on `lastSeq[aid] > 0` so the initial join doesn't false-positive against a pre-existing stream. Hammer instrument skips when the snapshot read for `endAtMs` fails — better to lose the metric than poison the histogram.
- **Concurrency** — every counter is `atomic.Int64`; every histogram observation takes a per-histogram mutex briefly (cheaper than a global rwlock, and the bid path is ~100 obs/s in the worst case). `TestHistogramConcurrent` proves no observation is lost under 16-way contention. The race detector runs in `ci.go` test step (`-race`), so any new write site that misses the lock surfaces on CI before merge.
- **Perf cost** — per-bid: one `atomic.Int64.Add` + one mutex-protected slice replacement (~50 ns each at default Go mutex overhead). Negligible vs the Lua RTT we're trying to observe.
- **Security** — `/metrics` exposes no per-user / per-auction PII (just aggregates). Behind dev-login at the same level as the room snapshot otherwise. Noted in `apps/lumen/internal/server/metrics.go` for the §8 follow-up hardening pass.
- **API** — no REST/WS contract change. `GET /metrics` is an additive operational endpoint, mirrored after the existing `GET /healthz` (no auth, JSON body, single shape).
- **AI edge cases / hidden tests** — load-report breach matrix has 9 cases covering every detector branch (ack/broadcast/hammer/script/seqGap/no-samples/hammer-count-zero) so a wire-up regression on a single instrument shows up here, not on the perf-report.md number that drifts silently. `eventServerTimeMs` table covers malformed payloads so the broadcast-latency extractor never panics on a future event type that lacks the field.

## Deferred (honest)

- The `docs/perf-report.md` numbers are a template (topology slot empty; budget table present). A real run needs the team box / deploy stack; this PR ships the rails so the run captures structured data the report can be filled from.
- Stream MAXLEN trim (V9 §10 T8 footnote: "MAXLEN trim must be ≥ this run's events, else trim drops the Verifier diff range and the verifier false-reports `mismatch`") is not yet enforced by the harness — the default load creates ~6k events which is well under any reasonable trim, and our current `XADD` uses no trim. A follow-up should add `MAXLEN` to the persistence sweep AFTER the verifier ran (T9 chaos consideration); flagged in the perf-report template.
- `proto/observed.md` (metrics shape canonicalization, V9 §6 contract follow-up) — defer to after T9 chaos; ship the metric names + shapes here as the de-facto canonical, and harden when there's a second consumer.
- Hammer latency captures detection-lag + Lua exec but NOT broadcast-to-last-viewer (that lands in `broadcastLatencyMs` for AUCTION_SOLD/NO_BID). The report adds them in §3 for the V9 §4.2 P0 hammer-budget assertion.
- Gateway topology vs Hub multi-instance: the harness measures on a single-gateway box (matches `docker-compose.yml`). Multi-gateway P0 ratification (T5 acceptance) already shipped — running `make load` against a multi-gateway deploy is a stretch follow-up.
