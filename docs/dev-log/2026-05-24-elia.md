## Entry 1 — T2 implementation

**What changed** — turned T1's accept-any `place_bid.lua` into the full atomic bid core (V9 §10 T2):

1. **`place_bid.lua` — atomic state/amount/cap/dedupe/seq/anti-snipe/Stream/publish.**
   - Amount validation: reject `amount < currentPrice + increment` **or** `amount > cap` (single `ERR_TOO_LOW` namespace; `cap==0` = no ceiling).
   - **Anti-snipe** (`OK_EXTENDED`): bid within `extendWindowSec` of `endAtMs` bumps `endAtMs += extendSec*1000`, `HINCRBY extendCount`, emits `AUCTION_EXTENDED` — same script, no `extend.lua`.
   - **Cap-hit / buy-now** (`OK_SOLD`): `amount >= cap` → `status=SOLD` + `AUCTION_SOLD`. Cap-hit beats anti-snipe.
   - Secondary events **consume their own seq** (`seq+1`) so every Stream entry keeps a unique `<seq>-0` id and the log stays gap-free.
   - Leaderboard via `ZADD GT` (each member's accepted max).
2. **Typed Pub/Sub fanout** — Lua publishes `{type,seq,data}` (`PubMessage`); the gateway subscriber re-emits the right wire type (`BID_ACCEPTED`/`AUCTION_EXTENDED`/`AUCTION_SOLD`). One channel, N event types; Stream stays the source of truth.
3. **Client `seq-guard`** — `apps/lumen/internal/seqguard` (drop duplicate ack-vs-broadcast + out-of-order frames; `Gap()` for the T5 snapshot fallback). Mirrored in `web/room.html`, which now also renders the leaderboard, a countdown, and the extension/SOLD events.
4. **Leaderboard read** — `store.Leaderboard` + `GET /api/auctions/{id}/leaderboard?n=` (token-gated; money as string; n∈[1,100]).
5. **perf-smoke** — `lumen perf-smoke` + `make perf-smoke` + compose service: pipelined bids measuring ack/broadcast p50/95/99 vs §4.2 **fallback** budgets (ack<200ms, broadcast<500ms). Floor-check only (single gateway, no fixed box) — not the 500/50 SLO gate (T8).
6. **Contracts** — materialized the T2 `place_bid` return shape + `PubMessage` in `redis-keys.md`; `OK_EXTENDED`/`OK_SOLD` in `error-codes.md`; `AUCTION_EXTENDED`/`AUCTION_SOLD` data shapes + seq-guard + leaderboard in `ws-envelope.md`.
7. **CI** — added a `redis:7` service to the `go` job + `go test -race`, so the §4.1 / Lua-return-code suite runs as a real gate (not skipped). Added perf-smoke to the e2e job.

**How / decisions**
- **Lua hot path stays the only writer**; Go's `PlaceBid` just maps the return array. Anti-snipe/cap are branches inside the one script (no rollback risk).
- **Two events per extend/cap bid** (BID_ACCEPTED then AUCTION_EXTENDED/SOLD), each with its own seq — chosen over reusing one seq so `<seq>-0` stays unique and catchup/seq-guard see a contiguous log.
- **seq-guard is Go-first** (CI-gated pure logic, 100% covered) with a JS mirror for the demo client — the repo has no JS test runner yet, so the Go impl is the spec.
- **perf-smoke is a floor-check, deliberately**: green ≠ de-risked 500/50 (§4.2 note). CI uses the fallback budgets to stay non-flaky on shared runners.
