## Entry 1 — T3 implementation

**What changed** — added the time-driven terminal path (the hammer no longer depends on the next bid) + seller cancel.

1. **`close_auction.lua` — Timer-triggered hammer.** type-guard → require `status==LIVE` (else `ERR_ALREADY_TERMINAL`) → **Redis TIME re-check `now >= endAtMs`** (else `ERR_NOT_DUE(endAtMs, now)` — an anti-snipe extension since the scan) → stream/state seq preflight → `HINCRBY seq` → `winnerId != ''` ? `SOLD`/`AUCTION_SOLD` : `NO_BID`/`AUCTION_NO_BID` at `<seq>-0` → publish wakeup. Returns `OK_SOLD` · `OK_NO_BID` · `ERR_NOT_DUE` · `ERR_ALREADY_TERMINAL` · `ERR_INTERNAL`.
2. **`cancel_auction.lua` — seller/admin cancel** of a non-terminal frozen auction (SCHEDULED/LIVE). type-guard → reject terminal/absent (`ERR_ALREADY_TERMINAL`) → ownership `callerId == sellerId` (else `ERR_NOT_ALLOWED('not_owner')`) → seq preflight → `HINCRBY seq` → `CANCELLED`/`AUCTION_CANCELLED` at `<seq>-0`. Returns `OK_CANCELLED` · `ERR_NOT_ALLOWED` · `ERR_ALREADY_TERMINAL` · `ERR_INTERNAL`.
3. **Timer Worker** (`server/timer.go`) — the single hammer authority. 100ms scan of `auction:active` (ZSET, `member=auctionId score=endAtMs`); for each due id calls `close_auction`; on `OK_SOLD`/`OK_NO_BID`/`ERR_ALREADY_TERMINAL` → `UntrackActive`; on `ERR_NOT_DUE` → refresh the score to the new `endAtMs`. Runs in `--mode=all` and `--mode=timer`.
4. **Active index in the store** — `TrackActive`/`UntrackActive`/`DueAuctions(ZRANGEBYSCORE -inf..now)`/`RedisNowMs(TIME)`; `StartAuction` registers on `OK_LIVE`. The ZSET is **global (un-tagged)** so the Lua hot path never touches it — Go maintains it and `close_auction` re-checks Redis TIME, so a stale score only costs a retry, never a premature hammer.
5. **Terminal-status projection** — the **Persistence Worker** sets `auctions.status` for SOLD/NO_BID/CANCELLED from the Stream terminal event (single source: covers cap-hit SOLD via `place_bid`, the Timer hammer, and cancel). `freeze`/`start` (SCHEDULED/LIVE) stay set by their REST handlers (no Stream event).
6. **Cancel REST** — `POST /api/auctions/{id}/cancel`: ownership via MySQL → terminal→409 → DRAFT (unfrozen, no Redis state) is a MySQL-only status flip → else `cancel_auction` + untrack + status write.
7. **Contracts** — `redis-keys.md` (close/cancel sigs, `auction:active` semantics, projection note), `error-codes.md` (`OK_NO_BID`/`OK_CANCELLED`/`ERR_NOT_DUE`/`ERR_ALREADY_TERMINAL` + pinned oracle), `ws-envelope.md` (`AUCTION_NO_BID`/`AUCTION_CANCELLED` shapes).

**How / decisions**
- **Lua stays the only writer**; the Timer is just a clock that calls `close_auction`. The `now >= endAtMs` re-check inside Lua — not the ZSET score — is the authoritative expiry gate, so anti-snipe (which extends `endAtMs` in state but never touches the un-tagged active ZSET) can't be hammered early: a stale-score scan lands as `ERR_NOT_DUE` and refreshes.
- **Status projection is event-sourced, not handler-scattered** — one terminal-event→status mapping in the persistence worker covers all three terminal causes, so cap-hit SOLD (which has no Timer involvement) and the hammer share one path.
- **DRAFT cancel is MySQL-only** — an unfrozen auction has no Redis room/stream, so there's nothing for Lua to do.

**Tests / evidence** — `lua_t3_test.go` (real Redis): every close/cancel return code, SOLD/NO_BID snapshots, gap-free `<seq>-0` stream, post-terminal `ERR_NOT_LIVE`, the §4.1 hammer-race oracle. `ws_t3_test.go` (in-process harness: Redis+MySQL+hub+persistence+timer): Timer hammer → `AUCTION_SOLD` room broadcast + MySQL SOLD projection; cancel LIVE → `AUCTION_CANCELLED` + CANCELLED; DRAFT cancel + non-owner 403 + re-cancel 409.

## Entry 2 — independent review (docs/review.md) + fixes

Ran an independent reviewer over the full T3 diff (correctness · concurrency · Lua no-rollback · security · API/plan-compat), with focus on the Timer↔anti-snipe↔active-set race. Fixed the valid findings; re-ran the whole suite `-race` after.

**Fixed**
- **[CRITICAL] lost-auction on a post-`OK_LIVE` track failure** — `StartAuction` ran `start_auction.lua` (commits LIVE atomically) then `ZADD`ed the active index and *returned the ZADD error*. A blip there meant: auction LIVE in Redis, absent from the Timer index, retry hits `ERR_BAD_STATE` → **never hammered**. Fix: (a) `TrackActive` is now **best-effort** on start (log, don't fail a committed-LIVE start); (b) the Timer gained a **reconcile** tick (5s + on startup) that walks the authoritative state Hashes (`ScanStateAIDs`) and re-registers any `LIVE` auction missing from the index. The state Hash (Lua-atomic) is the source of truth for membership; the ZSET is a rebuildable cache. Self-heals within one reconcile tick.
- **[HIGH] `cancel_auction.lua` ownership failed open** — `if sellerId ~= '' and callerId ~= sellerId` skipped the check when `sellerId` was empty. A terminal-writing op should fail **closed**: now rejects unless `sellerId` is present and equals `callerId`. (Contrast `place_bid`'s seller-self-bid check, which fails open because there the safe default is "accept the bid"; here it's "deny the cancel".)
- **[HIGH] pinned oracle only tested sequentially** — added `TestT3HammerRaceConcurrentLateBidNeverWins`: late bid + close dispatched from two goroutines past `endAtMs`. Redis serializes the two scripts, so order is nondeterministic, but the invariant holds either way — the late bid is **never accepted** (`ERR_AFTER_END` if it wins dispatch, `ERR_NOT_LIVE` if the close beat it), close is `OK_SOLD`, winner stays the pre-expiry bidder, exactly one extra seq. Green under `-race`.
- **[MEDIUM] flake-prone 400ms window** in `TestT3TimerHammerEndToEnd` — a slow CI runner could let the WS bid land after the hammer (`ERR_AFTER_END`). Widened to 1500ms (bid still lands well before expiry; hammer still fires inside the 5s wait).
- **[MEDIUM/LOW] silent error discards** — the `ERR_NOT_DUE` retrack and `handleCancel`'s untrack now log on failure (both self-heal, but a silent prod failure is undiagnosable).
- **[LOW] missing assertion** — `TestCancelAuctionScheduled` now asserts CANCELLED status + the single `AUCTION_CANCELLED@1-0` stream entry.

**Acknowledged / deferred (with reason)**
- **Persistence `InsertEvent` + `UpdateAuctionStatus` are two statements, not one txn** — safe: `INSERT IGNORE` is idempotent and the cursor only advances after both succeed, so a crash between them re-projects correctly on the next sweep. Eventual consistency is the accepted design (REST status can briefly lag Redis on cap-hit SOLD).
- **Double Timer on `--mode=all` + a separate `--mode=timer`** — harmless: Redis serializes the two `close_auction` calls, the loser gets `ERR_ALREADY_TERMINAL` (no writes), both untrack idempotently. Single-Timer is the intended deployment (no distributed lock; out of scope per the plan).

**Tests / evidence** — full `go test -race -count=1 ./...` green with **zero skips**, in a CI-replica container (golang:1.22 + linked redis + mysql + schema, `REDIS_ADDR`/`MYSQL_DSN` as in `.github/workflows/ci.yml`); `gofmt`/`vet`/`build` clean. T3 suite: 10 store + 4 server tests PASS (incl. the new concurrent oracle), confirmed running (not skipped) via `-v`. CI needs no change — the T3 tests are standard `_test.go` in existing packages, so the `go` job's `-race ./...` + no-`--- SKIP` gate already covers them.
